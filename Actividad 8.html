Objetivo del Laboratorio

2. Explicación Técnica de la Vulnerabilidad

En muchas ocasiones, los desarrolladores intentan defenderse contra los ataques de Path Traversal bloqueando explícitamente secuencias de caracteres como ../ o sus representaciones codificadas. Sin embargo, si la validación solo se enfoca en bloquear saltos relativos, es posible evadir este filtro utilizando una ruta absoluta. Una ruta absoluta especifica la ubicación exacta del archivo desde el directorio raíz del sistema de archivos (ej. /etc/passwd), permitiendo acceder a archivos sensibles sin necesidad de navegar hacia arriba en la estructura de directorios.

4. Explicación del Payload

/etc/passwd

A diferencia del ejercicio anterior donde se utilizaban saltos de directorio (../../../), en este caso la aplicación web filtra o bloquea dichas secuencias relativas para protegerse. Al ingresar directamente la ruta absoluta del archivo objetivo en el sistema de archivos del servidor, logramos evadir la regla de bloqueo. El sistema procesa la ruta tal cual se recibe y devuelve exitosamente la información solicitada sin requerir manipulación de saltos.

5. Mitigación Recomendada

La defensa implementada por el desarrollador en este laboratorio (bloquear ../) fue insuficiente, ya que es una estrategia basada en "lista negra" (Blacklisting).

  • Se recomienda utilizar validaciones mediante listas blancas (Whitelisting) validando que el archivo solicitado corresponda únicamente a nombres de archivos esperados.
  • Utilizar las APIs del sistema operativo para normalizar las rutas absolutas y verificar que el archivo de destino resida siempre dentro del directorio raíz previsto para la aplicación.
